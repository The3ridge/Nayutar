# 0018: G0 の合格条件を定める

## コンテキスト

[[0001]] の決定 7 は、ゲート G0〜G4 の内容を調査本文 §10.3 を出発点とし、個々のゲートの合格条件は別の ADR で定める、と決めた。同 ADR の影響節は、最初に G0 の合格条件を ADR として定める、と書いた。調査本文の所在は `docs/research/poc.md` である。

§10.3 の G0 は「仕様とハーネス」である。実証内容は、形式仕様（ストア・所有権・ESR）、決定論的シミュレータ、Kubernetes 差分ハーネスである。最初に検証する仮説は「Kubernetes をオラクルにした差分試験が自動で回る」である。

件数の初期値は、受け入れ済みの [[0003]] がすでに書いている。[[0017]] は [[0003]] の実現を二段に分ける決定であり、G0 の合格条件を定める ADR ではない。

## 決定

G0（仕様とハーネス）に合格するのは、次をすべて満たしたときである。[[0003]] が初期値とした件数を変えるときは、本 ADR を `supersedes` する。本 ADR は、これらの条件を満たしたとは主張しない。

1. **仮説。** `docs/research/poc.md` §10.3 の仮説「Kubernetes をオラクルにした差分試験が自動で回る」が成り立つ。その実証として、kind 上の Kubernetes v1.37 に対する差分が 30 シナリオ以上、偽陽性 0 件で通る（いずれも [[0003]] の初期値）。kwok は [[0003]] の決定 4 がオラクルに含める。シナリオ件数の初期値は kind 差分にだけ書かれているので、kwok に別の件数は置かない。
2. **ストア／watch の DRT。** Lean と Go の差分ランダムテストが 1,000 ケース通る（[[0003]] の初期値）。
3. **所有権 CAS の DRT。** 所有権 CAS 版の Lean と Go の差分ランダムテストが 1,000 ケース通る（[[0003]] の初期値）。
4. **watch の不変条件。** [[0007]] が定める 4 件を Lean で証明する。[[0007]] の本文が現在挙げている 4 件は、欠落なし、重複なし、順序保存、ブックマーク単調性である。4 という件数は [[0003]] が受け入れた値である。[[0007]] は `proposed` であり、4 件の名前を変える決定は [[0007]] 側で行う。
5. **所有権の証明。** 所有権の CAS 版プロトコルモデルを、[[0013]] が定める範囲で証明する。[[0013]] は `proposed` であり、本 ADR は性質の個数や `sorry` の有無を新設しない。
6. **ESR。** ESR は Lean 4 上の抽象状態機械で証明し、Go コード上では証明しない（[[0003]] の決定 3）。対象にするコントローラは本 ADR で新設しない。
7. **CI の流量。** PR では DRT を 1,000 ケース、マージ後は 10,000 ケース流す（[[0003]] の根拠が初期値とした値）。これは流量であり、2 と 3 の領域ごとの合格件数を満たしたことにはならない。
8. **枠組み用の DRT は数えない。** [[0017]] の極小レジスタに対する DRT は、2 と 3 を満たしたことにはならない。2、3、1 の kind 差分、5、6 を実装で満たす作業は、[[0017]] が決定 7 で後続へ送っている。本 ADR はその実装を行わない。[[0017]] の status は変えない。
9. **決定論的シミュレータ。** §10.3 の実証内容に含まれる。数値の合格条件は [[0003]] にも [[0017]] にも無いので、本 ADR は新設しない。[[0015]] は `proposed` であり、そこに書かれた実行回数は本 ADR の合格条件にしない。

## 根拠（調査結果・出典）

- **ゲートの出発点**（`docs/research/poc.md` §10.3）：G0 の行は、実証内容を「形式仕様（ストア・所有権・ESR）、決定論的シミュレータ、Kubernetes 差分ハーネス」、仮説を「Kubernetes をオラクルにした差分試験が自動で回る」と書く。§10.3 はこの 5 ゲートの表以外に件数を置いていない。
- **受け入れ済みの初期値**（[[0003]] の影響節）：「G0 で Lean–Go DRT（ストア／watch・所有権 CAS 版各 1,000 ケース、初期値）、所有権の CAS 版プロトコルモデルの証明（範囲は [[0013]] で定める）、watch 不変条件 4 件（[[0007]]）、kind v1.37 差分 30 シナリオ以上（偽陽性 0 件、初期値）を検証する。」決定 3 は ESR を Lean 4 上の抽象状態機械で証明し、Go コード上では証明しない、と決める。決定 4 は Kubernetes v1.37 系（kind および kwok）を外部オラクルとする、と決める。
- **流量の初期値**（[[0003]] の根拠節）：「G0 の DRT 各 1,000 ケース・kind 差分 30 シナリオ以上、PR 時 DRT 1,000・マージ後 10,000 などの件数はいずれも初期値とする（同 §7.4・§8.1）。」ここで「同」は `docs/research/draft_20261117_001.md` を指す。§7.4 は PR の DRT 1,000 と、マージ後の DRT 10,000 を書く。§8.1 の合格基準 1 と 2 は、kind v1.37 に対する 30 本以上のシナリオが毎晩完走し偽陽性が 1 週間 0 件であること、およびストア／watch の DRT と所有権 CAS 版の DRT がそれぞれ 1,000 ケース通ることである。
- **採らなかった §8.1 の残りの項目**（`docs/research/draft_20261117_001.md` §8.1）：同じ節は、同一シード 100 回のトレースハッシュ一致と、CI だけでマージされた PR の割合の計測も合格基準に挙げている。[[0003]] の G0 の文はこれらを合格条件にしていない。本 ADR も合格条件にしない。
- **watch の 4 件の現在の名前**（[[0007]] の決定 7）：「欠落なし・重複なし・順序保存・ブックマーク単調性」。[[0007]] の影響節は、これに加えてストア／watch の DRT 1,000 ケース以上と線形化可能性検査を G0 で検証する、と書く。線形化可能性検査は [[0003]] の G0 の文には無い。[[0007]] が `proposed` であるうちは、本 ADR の合格条件に加えない。
- **所有権の証明範囲の現在の文**（[[0013]] の影響節）：「Plan 安全性 11 性質と新プロトコル不変条件の証明（`sorry` ゼロ）」、および [[0003]] の DRT 1,000 ケース、3 か月で証明できなければフィールドグループ単位へ粗粒化する、と書く。これらは [[0013]] が `proposed` の本文であり、本 ADR の決定 5 はその範囲を [[0013]] に委ねる。
- **枠組みは G0 の件数ではない**（[[0017]] の影響節）：「G0 の合格基準（ストア／watch と所有権 CAS 版の DRT 各 1,000 ケース、kind v1.37 差分 30 シナリオ以上）は、7 に挙げた後続の実装で満たす。」決定 5 は極小レジスタを製品のモデルではないと書き、決定 7 はストア／watch、所有権／apply、パス写像、ESR、Kubernetes v1.37、Welder の 2 原則を後続へ送る。

## 検討した代替案

- **合格条件を [[0003]] の影響節に置いたままにする**：件数の出典はそこにある。しかし [[0001]] は、合格条件を別の ADR の決定として定めると決めており、影響節の一文はレビューが求めた「決定本文」にはならないため採らない。
- **[[0017]] を G0 の合格条件の ADR とみなす**：[[0017]] は枠組みと後続への送り先を決める決定であり、合格条件の一覧ではない。極小レジスタの DRT を G0 の 1,000 ケースと数えることになるため採らない。
- **`docs/research/draft_20261117_001.md` §8.1 と [[0015]] の数値をすべて合格条件にする**：同一シード 100 回、CI マージ割合、シミュレータの実行回数まで一枚の条件にできる。しかし [[0003]] が G0 の文に採らなかった項目と、`proposed` の [[0015]] の回数を、受理済みの条件として新設することになるため採らない。
- **エージェントが起票時点で勝手に `accepted` にする**：受理は所有者の判断で行うため採らない。

## 影響とトレードオフ

- **得るもの**：G0 に何が揃えば合格かを、[[0001]] が求めた別 ADR の決定として参照できる。極小レジスタの DRT を、ストア／watch や所有権 CAS の合格件数と取り違えない。
- **失うもの**：[[0007]]・[[0013]]・[[0015]] が `proposed` の間、watch の 4 件の名前、所有権証明の範囲、シミュレータの回数は、本 ADR の中では閉じない。
- **引き受けるリスク**：本 ADR や [[0017]] を受理しても、条件を満たす実装ができたことにはならない。[[0007]]・[[0013]]・[[0015]] が `proposed` の間、それらが担う細目は未確定のまま残る。
- **今後の検証ゲート**：G0 の合格は、上の決定 1〜7 が揃ったときに判定する。決定 9 のシミュレータに数値を置くときは、[[0015]] を受理するか、本 ADR を `supersedes` する ADR で行う。
