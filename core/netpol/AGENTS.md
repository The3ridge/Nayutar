# core/netpol — 既定拒否ネットワークポリシーと nftables 強制

`core/netpol/` で作業するときの指示。共通の指示はリポジトリのルートの `AGENTS.md` にあり、ここには繰り返さない。

- 決定は ADR 0016（`accepted`）、実現方式は ADR 0033（`accepted`）、実データプレーンの穴を塞ぐ補強は ADR 0034（`accepted`）。`br_netfilter` に依存せず、テナント別 Linux ブリッジ（`nbr-<sha256(tenant)[:11]>`）と非重複テナント CIDR で全テナント越境通信をホスト L3 `table inet nayutar` の `chain forward`（`policy drop`）へ通す。
- 層は 3 つ。
  1. 純粋核（`prefix.go`・`netpol.go`・`nft.go`）：ゴルーチン・時計・網・ディスク・`os/exec` を持たない決定論的コンパイラ・評価器・`nftables` AST 変換器。Lean 4 モデル `spec/Nayutar/Netpol.lean` と DRT（`nayutar-drt netpol`）で照合する。DRT が比べるのは `Compile` の受理・拒否とエラーコード、`Evaluate` と `EvalNft` の判定、`CompileNft` の表の全体（チェインの順序・名前・既定ポリシーと各規則の一致項目・動作）であり、`RenderNft` の出力テキスト、ガードのチェイン、`bridge` のミラーは比べない（実カーネル試験だけが確かめる）。どちらかを変えるときは両方を変える。Lean に無い入力（未知の `ConnState`・未知の `PeerKind`）は Go だけで fail-closed にする。
  2. スキーマ（`netpol.schema.lkal`・`kind.schema.lkal`・`schema.go`）：スタンドアロン束と `net.nayutar/networkpolicy` `KindSchema`（`order` 必須の順序付き集合、相手テナントは `.string`）。kind は `intraTenant` と許可ルールだけを持ち、CIDR は持たない（`DecodeTenantPolicySpec` が呼び出し側から受け取る）。CIDR を持つのはスタンドアロン束だけで、`DecodeBundle` が配備前検査も通す。
  3. 実行器（`enforcer.go`）：`os/exec` を使う唯一のファイル。シンボリックリンク解決と実行可能通常ファイル検査を経た `nft` へ `"-f", "-"` で原子的置換バッチ（`table` → `delete table` → `table { ... }`）を標準入力で渡す。`flush ruleset` は絶対に使わない。`nft` は root 所有かつ group・other 書き込み不可で、その親ディレクトリも `/` まで全て root 所有かつ group・other 書き込み不可でなければならない（sticky の world-writable も不可）。`Enforcer` は `sim.Disk`（本番は `SysctlNetDir` = `/proc/sys/net` を根にした `sim.RootedDisk`）を受け取り、政策を入れる前に必ず（`Apply`・`ApplyCompiled`。`Teardown` は除く）`net.bridge.bridge-nf-call-iptables`・`bridge-nf-call-ip6tables` が 0 か不在であることを検査し、違えば `ErrBridgeNetfilterEnabled` で拒否する（`br_netfilter` が有効だとブリッジ越しのフレームが `inet forward` に入り、結果が変わるため）。1 回の実行には `sim.Clock` で測る期限（既定 30 秒）がある。
- 異テナント間の新規通信は送信側の `egress` と受信側の `ingress` の**双方が一致したときのみ**許可し、片側許可では必ず遮断する。
- 通常の `go test ./core/netpol/...` は root・カーネル・ネットワークを要さず、`FakeNftRunner`・`sim.MemDisk`・`testing/synctest` で動く（一部の試験は `sleep` など実プロセスを起動する）。`t.Skip` は禁止。実 root + Linux `netns` + CNI ブリッジ + 実 `nftables` の試験は `nftables_linux_test.go`・`nftables_binding_linux_test.go`・`nftables_input_linux_test.go`（`//go:build linux && nftables`）に置く。
- 実カーネルの強制は純粋核の外にある追加でできていて、**Lean モデルに入っていない**。正しさは実カーネル試験だけが保証する（束縛規則を消すと落ちることを変異で確かめてある）。`CompileNft` の `NftTable` はこれらを含まない。
  - `guard_forward`（`table inet nayutar`、priority -10）：(1) `nbr-*` の入出口で、政策に無いテナントブリッジは丸ごと `drop`（テナント 0 なら `nbr-*` を全 `drop`）。(2) テナントの送信元アドレスを入口ブリッジ（`TenantBridgeName`）へ束縛し、そのテナントの CIDR を持たない族は `nbr-<T>` から来たものを丸ごと `drop`。(3) 宛先も束縛する：`oifname != "nbr-<T>"` で宛先がテナント CIDR のものは `drop`（出口もそのブリッジに限る）。
  - `guard_input`（hook input）：順序が意味を持つ。(1) 最初に束に無い `nbr-*` ブリッジからの入力を `drop` する（テナント 0 なら `iifname "nbr-*" drop` のみで終了し、残存コンテナが近隣探索や `ct state` に到達するのを防ぐ）。(2) `iifname "nbr-*"` の近隣探索（NS・NA・RS）を許す（リンクスコープで、リンクローカルや未指定の送信元を使うので束縛の対象にしない）。(3) テナントごとに `nbr-<T>` から来た送信元をそのテナントの CIDR に束縛し（CIDR の無い族は丸ごと `drop`）、(4) テナントの送信元を名乗るのに `nbr-<T>` でも `lo` でもない入口から来たパケットは `drop`（`lo` を除くのはホスト自身がゲートウェイアドレスへ話すとき、テナント CIDR の送信元で `lo` を通るため。非テナントのインターフェースを見る唯一の規則）。(5) その後ろで `nbr-*` の確立済みを許し、ICMP echo は `nbr-<T>` ごとに宛先をそのテナントの CIDR に束縛した規則だけで許し（他テナントのゲートウェイやホストのその他のアドレスへの ping は通らない）、残りの `nbr-*` を `drop`。束縛が確立済みより前にあるのは、偽装した送信元でホストに echo を反射させたり、ホストの会話へ偽返信を差し込んだりさせないため。
  - `table bridge nayutar`：`intraTenant = deny` のテナントがあるときだけ出す。`meta ibrname` でそれらのブリッジに絞り、ARP と近隣探索（NS/NA）を許し、ルータ要請・広告は `drop`、IP 以外を `drop`。その後ろで `ct` の規則より前に、`deny` テナントごとに `meta ibrname "nbr-<T>"` で IP の送信元・宛先をそのテナントの CIDR に束縛する（CIDR を持たない族は `ether type ip(6)` を丸ごと `drop`）。L2 フレームはブリッジ内でコンテナ同士にしか届かないので、L3 ヘッダだけで判定すると偽装送信元・汚染 ARP・routed フロー用の conntrack に便乗した偽返信が通るため。ARP の送信元アドレスの束縛は範囲外（ARP は許すだけ）。束縛の後ろに同じ `NftTable` の `forward` 規則（外部 egress 完了の無条件 `accept` を除く）とテナントチェインを機械的に出力し、末尾は無条件 `drop`。`nf_conntrack_bridge` が無いと適用に失敗する（fail-closed）。
  - バッチは常に `inet` と `bridge` の `table` → `delete table` を両方先頭に出す。`RenderTeardownNft` も両方消す。ガードのチェイン名は `forward`・`tenant_*` と衝突しない。
- 配備前検査（`CheckDeployable`、`deploy.go`）は `Compile` の外にある。`/0`、`::ffff:0:0/96` と重なる IPv6 CIDR、`TenantBridgeName` が衝突するテナントの組を `DeployError` で拒否する。`Enforcer.Apply`・`ApplyCompiled`・`RenderNft`・`DecodeBundle` が通す。`RenderNft` は `Compile` と同じ検証を通った入力しか出力せず、`error` を返す。
- `ExecNftRunner` の所有者検査は root（uid 0）固定で、試験だけが `export_test.go` で別の uid を信頼させ、親ディレクトリの検査を省く（非特権ユーザー名前空間では root 所有のファイルの uid が写らない）。実カーネル試験は `unshare -Urnm` の中でも動く。
