# core/sim — シミュレーション境界と決定論的イベントキュー

`core/sim/` で作業するときの指示。共通の指示はリポジトリのルートの `AGENTS.md` にあり、ここには繰り返さない。パスはリポジトリのルートからの相対で書いてある。

- 決定は ADR 0015（`accepted`）、実現方式は ADR 0032（`accepted`）。`gosim` は採用せず、`Clock`・`Net`・`Disk`・`Rand` の 4 インターフェースと単一スレッド離散イベントキュー `Queue` で外界隔離と決定論性を実現する。
- 実環境実装（`RealClock`・`RealNet`・`OSDisk`・`NewRootedDisk`・`CryptoRand`）は `interfaces.go` に閉じ込め、`core/boundaries_test.go` の AST 検査で他パッケージからの標準ライブラリ直接呼び出しを禁止する。
- `NewDetRand` / `NewDetRandStream` は `math/rand/v2.ChaCha8` の `Uint64()` のみを使い、`Fill` でも `ChaCha8.Read` を混ぜない（クロスアーキテクチャ・Go 版跨ぎのビット一致を守る）。
- `FakeClock`・`Queue` は浮動小数点を使わず `(deadline/atMs, seq)` の最小ヒープで決定論的に発火させる。`WithTimeout` は注入時計に従いタイムアウト時に `context.DeadlineExceeded` を返す。
- `MemNet` は `net.Pipe` 上の仮想交換機として実装し、`testing/synctest` バブル内で durably blocked として動かす。実ソケットを開かない。切断・分断・片方向ドロップに加え、`SetDelay`（既定）と `SetLinkDelay`（リンク別、0 や負値での解除を含む上書き）で遅延を注入する。遅延は配送遅延で、`Write` は遅延が 0 でない限り待たずに（書き込み期限もここまで）コピーを方向別の順序つきキューに積む。遅延 0 の `Write` も同じキューに積み、自分のバイトがパイプに渡される（相手が読む）まで、完了・`Close`・書き込み期限のチャネルだけで待つ（`net.Pipe` と同じ同期的な背圧）。`inner.Write` を呼ぶのは接続ごとのポンプだけで、同時に 1 つだけ。ポンプは `NewMemNetWithClock` の `Clock` の取り消し可能タイマ（とチャネル）だけで待って配送する（mutex を握ったまま時計を待たないので、バブル内で durably blocked になり、HTTP/2 のように mutex 越しに並行して書いても止まらない）。バイト順は接続内で保たれ（遅延の切り替え中も）、N 個のパイプライン書き込みは 1 遅延で届く。読み取り・書き込みの期限はどちらも注入した `Clock` で判定する（`net.Pipe` の実時間期限は使わない）ので、`FakeClock` でも `RealClock` でも同じ振る舞いになる。期限を過去へ動かすと待機中の `Read`/`Write` は `os.ErrDeadlineExceeded` を満たす timeout で戻る。配送時点で切断・分断・片方向ドロップが効いていれば飛行中のデータは捨てる。TCP との違い: `Close` は未配送データを捨ててタイマを止める（TCP のように flush してから FIN を送らない）ので、遅延下の graceful shutdown はテストできない。キューに上限はなく（遅延付きの `Write` に背圧は無い）、書き込み側が読み側より速いとメモリが増える。
- `RootedDisk` は `os.Root` 上に実装し、カーネルが `..`・シンボリックリンク・絶対パスによるルート外脱出を拒否する（パス解決後に別パスで開く TOCTOU を持たない）。ルート内を指す絶対パスのシンボリックリンクも `os.Root` は辿らない。
- `core/sim/clustersim` はストア・watch キャッシュ・リソース所有権・死活監視・ノードライフサイクルを単一 `Queue` と単一シードで結合駆動し、同一シード 100 回実行での `TraceHash` 完全一致と不変条件を検証する。不変条件は部品ごとの整合に加えて結合そのものを見る（停止・退避したノードに `Running` のユニットが無い、`Running` のユニットはそのノードの desired にある、障害を解いた後に各ノードの desired がキーごとのリビジョンと値までストアと一致し、健全なノードでは desired のユニットが `Running` か遷移の途中にある、キャッシュの一貫読み取りがストアの現在のリビジョン以上で答える、watch の配信がストアの履歴と欠落・重複・順序違いなく合う、新しいトークンの操作が古い所有リビジョンとして拒否されない）。不変条件を足すか変えるときは、`Config.Mutations`（ゼロ値は何もしない。わざと壊すための変異フック）に対応する変異を足し、`TestInvariantsCatchSabotage` で検出されることを確かめる。操作ごとに許す誤りは `expectedFailures` の表にあり、表に無い誤りは違反である。障害が各層に届いたかの集計試験は、環境変数に依らない固定のシード列で回す。シード制御は `NAYUTAR_SIM_SEED` / `NAYUTAR_SIM_SEEDS` と `RegressionSeeds` を使う。
- `RunSeeds` は `testing` を import しないよう最小の `SeedT` インターフェースを受け取る（本番バイナリに `testing` をリンクさせない）。`nodesim` が `RunSeeds` を使い、`livesim` は `ConfigFromEnv` と自前の失敗報告を使う（どちらも `NewDetRand(Stream)` を使う）。`NewRootedDisk` が返す `*RootedDisk` は `Close` で `os.Root` を解放する（`Disk` インターフェースには `Close` を足さない）。
